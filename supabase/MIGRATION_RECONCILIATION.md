The legacy badge tables already use `badge_code` and `rule`. The
`202611010004` migration describes a different badge shape, but its table
creation is guarded by `IF NOT EXISTS`; its remaining badge policy uses only
`user_id`. The production deployment preserved the live badge schema.

The first deployment attempt stopped at the `question_ids` text-to-JSONB
conversion in `202611010004`; that migration rolled back. The local migration
was corrected with `staging.normalize_legacy_question_ids`, which supports a
JSON array, a JSON-encoded array string, a comma-separated string, and null.
The helper was checked with read-only SQL for all four input forms.

Supabase CLI then applied `202611010002`, `202611010003`, and the corrected
`202611010004`. Post-deploy verification confirmed all nine reconciled versions
are recorded, the expected tables and functions exist, the key read policies
are present, and both required practice-session columns exist.

`migration repair` changed only the migration ledger for the six verified
versions; `db push` applied the three schema migrations. At that point, the
CLI history confirmed all 46 then-local versions matched the remote ledger.
